## Логирование
Инструкция по логированию через HTTP API

1. Отправляйте POST-запросы на эндпоинт
URL: http://localhost:8000/api/v1/logs - нужно вынести в настройку
Метод: POST
Заголовки:

Content-Type: application/json
X-API-Key: secret-key-for-hh-browser - нужно вынести в настройку

Тело запроса (JSON):

json
{
  "project": "my-bot", - значение в настройку
  "level": "info",
  "message": "Событие",
  "timestamp": "2025-05-03T10:00:00Z",
  "metadata": {"anything": "value"}
}
level может быть: debug, info, warn, error.
metadata — любой JSON объект (опционально).

2. Что важно знать
Сервис асинхронный, не блокирует ваш код.
Все логи хранятся в PostgreSQL, схема disa_logger_sh, таблица t_disa_logs.
Можно слать много запросов — нагрузка умеренная.
Для проверки работоспособности сервиса используйте GET /health (не требует ключа).


## Формирование идентификатора 
для каждого запуска расширения необходимо сформировать уникальный идентификатор. Этот идентификатор нужно будет передавать в каждом вызове логирования. идентификатор визуально должен содержать кроме других символов текущее время в формата чч:мм

## вывод настроек
все настройки необходимо передать через сервис логирования в одном сообщении в метадата

## Д1
1. сформировать идентификатор
2. вывести в лог мессадж="начало", левел=инфо, метадата = все настройки

## Д2
1. Найти элемент навигационного меню с атрибутом `data-qa="mainmenu_profileAndResumes"`
2. Если элемент найден и кликабельный, значит пользователь залогинен
3. Если элемент не найден, значит пользователь не залогинен

## Д3
вывести в лог мессадж="залогинен", левел -инфо, метадата - урл текущей страницы

## Д4
вывести в лог мессадж - "не залогинен" левел - еррор, метадата - урл текущей страницы

## Д999
вывести в лог мессадж - "штатный конец работы", метадата - итоговое время работы
