# Техническое задание на разработку расширения HH Auto Extension

## Общие требования

**Язык общения:** русский

**Задание:** создать расширение для браузера Brave (на базе Chromium) для автоматических откликов на hh.ru

**Архитектура:** 
- Service Worker (background script) — основной скрипт, управляющий вкладками через `chrome.tabs` и `chrome.scripting` API
- Manifest V3 — современная версия манифеста расширений Chrome

---

## Алгоритм работы расширения

### Шаг 1: Проверка авторизации

**Действие:** Проверяет выполнен ли вход в систему на сайте hh.ru

**Алгоритм:**
1. Найти элемент навигационного меню с атрибутом `data-qa="mainmenu_profileAndResumes"`
2. Если элемент найден и кликабельный → пользователь залогинен, продолжаем выполнение
3. Если элемент не найден → вывести в консоль `"Не залогинен. Останов"` и прекратить выполнение

**Вывод в консоль при успехе:** `"Авторизация подтверждена"`

---

### Шаг 2: Переход на начальную страницу

**Действие:** Переходит на страницу https://vidnoe.hh.ru/?hhtmFrom=main

**Алгоритм:**
1. Создать новую вкладку с URL `https://vidnoe.hh.ru/?hhtmFrom=main`
2. Дождаться окончания загрузки страницы (событие `onUpdated` с статусом `complete`)
3. Добавить случайную паузу (настройка `CONFIG.minDelay` / `CONFIG.maxDelay`)

**Вывод в консоль при успехе:** `"перешел на начальную страницу"`

---

### Шаг 3: Переход к списку резюме

**Действие:** В новой вкладке открывает страницу списка резюме пользователя

**Алгоритм:**
1. Создать новую вкладку с URL `https://vidnoe.hh.ru/applicant/resumes`
2. Дождаться окончания загрузки страницы
3. URL должен содержать `/applicant/resumes`

**Вывод в консоль при успехе:** `"перешел на список резюме"`

---

### Шаг 4: Получение списка резюме (АВВР1)

**Действие:** Выводит в консоль список всех названий резюме

**Алгоритм (АВВР1):**

1. Найти все карточки резюме:
   - Основной метод: элементы с атрибутом `data-qa^="resume-card-link-"` (начинается с)
   - Альтернативный метод: все ссылки с `href` содержащим `/resume/`

2. Для каждой карточки извлечь:
   - **Должность** — элемент с `data-qa="resume-title"`, внутри элемент с `data-qa="cell-text-content"`
   - **Ссылка на резюме** — атрибут `href` карточки

3. Удалить дубликаты по названию

4. Вывести список в консоль (каждое с новой строки)

**Обработка ошибок:**
- Если резюме не найдены → вывести `"не нашел ни одного резюме на url=<URL>"`, затем `"останов"` и прекратить работу

**Важно:** Обрабатываются ВСЕ резюме из списка, а не только "Аналитик"

---

### Шаг 5-9: Обработка каждого резюме

**Действие:** Для каждого резюме из списка выполнить шаги 5-9

**Алгоритм:**
1. Открыть резюме в новой вкладке
2. Найти ссылку на вакансии
3. Обработать вакансии
4. Закрыть вкладки резюме и вакансий
5. Перейти к следующему резюме

**Вывод в консоль:** `"=== Обработка резюме N/M: <название> ==="`

---

### Шаг 5: Открытие резюме

**Действие:** Кликает по резюме и открывает его в новой вкладке

**Алгоритм:**
1. Найти ссылку на резюме (поиск по тексту ссылки, содержащему название резюме без учёта регистра)
2. Создать новую вкладку с URL найденной ссылки
3. Дождаться загрузки страницы

**Вывод в консоль при успехе:** `"перешел на мое резюме = <название> ="`

**Обработка ошибок:**
- Если ссылка не найдена → вывести `"Не нашел ссылку на резюме <название>"` и перейти к следующему резюме

### Шаг 6: Поиск ссылки на вакансии

**Действие:** Находит ссылку на подходящие вакансии и переходит по ней

**Алгоритм:**
1. Найти ссылку одним из способов:
   - Текст ссылки содержит "подобрали для вас" и "подходящие вакансии"
   - Атрибут `href` содержит `/search/vacancy` и `resume=`
2. Создать новую вкладку с найденным URL
3. Дождаться загрузки страницы

**Вывод в консоль при успехе:** `"перешел на вакансии для резюме = <название> ="`

**Обработка ошибок:**
- Если ссылка не найдена → вывести `"Ссылка на вакансии не найдена для резюме <название>"`, закрыть вкладку резюме и перейти к следующему резюме

### Шаг 7: Получение списка вакансий

**Действие:** Находит первые 10 уникальных вакансий

**Алгоритм:**
1. Найти все карточки вакансий: `div[data-qa="vacancy-serp__vacancy"]`
2. Для каждой карточки извлечь:
   - **Ссылка** — элемент `a[data-qa="serp-item__title"]` или `a[href*="/vacancy/"]`
   - **Заголовок** — текст элемента с `data-qa="serp-item__title"`
   - **Исключить:** ссылки с `click` или `hot` в URL
   - если название вакансии содержит текст (без учета регистра) "разработчик", то эту вакансию нужно пропустить. на консоль выдать при этом название вакансии и пометку "=пропущено= в соответсвии с шаг7 ТЗ"
3. Удалить дубликаты по `href`
4. Ограничить список 10 вакансиями

**Вывод в консоль:** `"Найдено X уникальных вакансий"`

#### 8.5. Выбор резюме в модальном окне

**Интерфейс:** карточки резюме (не select)

**Входные данные:** `resumeName` — название резюме для поиска

**Алгоритм:**

**Шаг 1: Открытие списка резюме**
1. Найти элемент с `data-qa="resume-title"`
2. Найти кликабельный родительский элемент: `closest('[role="button"][tabindex="0"], button, [tabindex="0"]')`
3. Кликнуть на него
4. Подождать 1000мс

**Шаг 2: Сбор резюме**
1. Найти все элементы с `data-qa="resume-title"` во всём документе
2. Для каждого элемента извлечь название из `[data-qa="cell-text-content"]`
3. Удалить дубликаты по названию (использовать `Set`)
4. Вывести в консоль:
   - `"Найдено резюме в списке: X"`
   - `"Уникальных резюме: Y"`
   - Для каждого: `"Резюме N: <название>"`

**Шаг 3: Поиск нужного резюме**
1. Привести `resumeName` к нижнему регистру: `searchName`
2. Для каждого резюме проверить частичное совпадение:
   - `title.includes(searchName)` ИЛИ `searchName.includes(title)`
3. Если найдено — вывести `"Нашёл подходящее резюме: <название>"` и запомнить элемент
4. Продолжать поиск (не использовать `break`) — ищем более точное совпадение

**Шаг 4: Выбор резюме**
- Если резюме найдено:
  1. Найти кликабельный элемент: `closest('[role="button"][tabindex="0"], button, [tabindex="0"]')`
  2. Кликнуть на него
  3. Подождать 500мс
  4. Проверить: найти `[data-qa="resume-title"] [data-qa="cell-text-content"]` в модальном окне
  5. Вывести: `"Выбрано резюме: <название>"`

- Если резюме НЕ найдено:
  1. Найти контейнер скролла: `[data-qa="modal-content-scroll-container"]`
  2. Скроллировать вниз: `scrollTop = scrollHeight`
  3. Подождать 500мс
  4. Повторить скролл
  5. Подождать 500мс
  6. Повторить шаги 2-4 (сбор и поиск резюме)

**Важно:**
- Скроллировать ТОЛЬКО если резюме не найдено в начальном списке
- После скролла список может обновиться — нужно заново собрать все резюме

#### 8.9. Завершение обработки вакансии

**Действие:** Ожидает после отправки отклика и закрывает вкладку вакансии

**Алгоритм:**
1. После нажатия кнопки "Откликнуться" в модальном окне отправить сообщение в background script: `chrome.runtime.sendMessage({ action: 'responseSent' })`
2. Background script получает сообщение и ждёт `CONFIG.doneDelay` миллисекунд (по умолчанию 12000мс = 12 секунд)
3. Закрыть вкладку вакансии
4. Вывести в консоль: `"Закрыл вкладку вакансии id=<id>"`
5. Перейти к следующей вакансии

**Механизм сообщений:**
- Content script отправляет сообщение после отправки отклика
- Background script слушает сообщения через `chrome.runtime.onMessage.addListener()`
- После получения сообщения background script ждёт `doneDelay` и закрывает вкладку

## Конфигурация

Все параметры должны быть вынесены в объект `CONFIG` в начале файла:

```javascript
const CONFIG = {
  // Задержки (в миллисекундах)
  minDelay: 2000,           // Минимальная случайная пауза
  maxDelay: 4000,           // Максимальная случайная пауза
  doneDelay: 12000,         // Задержка после отправки отклика перед закрытием вкладки (12 сек)
```

## Технические требования

1. **Манифест:** Manifest V3
2. **Архитектура:** Service Worker (background script)
3. **API:** 
   - `chrome.tabs` — управление вкладками
   - `chrome.scripting` — инъекция скриптов
   - `chrome.action` — обработка клика по иконке

4. **Задержки:**
   - Случайные паузы между действиями (2-4 секунды)
   - Задержка между обработкой вакансий (7 секунд)
   - Задержка после клика на элементы (500-1500мс)

5. **Обработка ошибок:**
   - Все ошибки должны выводиться в консоль с понятными сообщениями
   - При критических ошибках работа должна останавливаться
   - При некритических ошибках — переход к следующей вакансии

6. **Код:**
   - Хорошо структурирован
   - Подробные комментарии на русском языке
   - Конфигурация вынесена в начало файла

## Особенности реализации

### 1. Уникальность резюме

При поиске резюме в модальном окне необходимо:
- Собирать все найденные элементы
- Фильтровать дубликаты по названию (использовать `Set`)
- Выводить только уникальные резюме

### 2. Скроллинг списка резюме

- Список резюме может скроллиться
- Скроллировать ТОЛЬКО если нужное резюме не найдено в начальном списке
- Скроллировать 2 раза для надежности
- После каждого скролла ждать 500мс

### 3. Вставка текста в textarea

- Textarea может быть уже открыт (проверять до нажатия кнопки)
- Искать textarea 4 разными способами
- Триггерить события: `input`, `change`, `blur`
- Фокусировать поле и снимать фокус

### 4. Выбор резюме

- Ищем частичное совпадение в обе стороны
- Не используем `break` — продолжаем искать более точное совпадение
- После клика проверяем, что резюме выбралось

## Логирование

Все действия должны логироваться в консоль с понятными сообщениями:

**Формат сообщений:**
- `"=== Начало работы HH Auto Extension ==="` — начало работы
- `"Шаг N: <описание>"` — начало шага
- `"<действие> успешно"` — успешное действие
- `"Ошибка: <описание>"` — ошибка
- `"=== Работа завершена ==="` — завершение работы

**Пример:**
```
=== Начало работы HH Auto Extension ===
Текущая вкладка: https://hh.ru
Авторизация подтверждена
Переход на vidnoe.hh.ru...
перешел на начальную страницу
...
=== Работа завершена ===
```
